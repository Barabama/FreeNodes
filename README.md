## 关于 merged 订阅

`merged.txt` 与 `merged.yaml` 在发布前做了三步处理：

1. **去重** — 按连接配置去重，同一节点被多个站点以不同名称重复发布时只保留一条；凭据或传输参数不同的节点不会被合并。
2. **过期源剔除** — 上次成功抓取早于 14 天的站点不再并入 merged，避免失效节点长期滞留。
3. **连通性筛选** — 默认对每个节点的端口做 TCP 握手，超过 3000 ms 或无法连接的节点会被移除。TCP 测速只说明端口在时限内可连，**不能验证代理认证或实际转发是否可用**；UDP 类协议（Hysteria2、TUIC 等）无法用 TCP 判定，一律保留。如需真实可用性，可将 `probe.backend` 改为 `mihomo`。

`provider.yaml` 引用的是各站点原始文件：已排除过期站点，但不做节点级去重与连通性筛选。
